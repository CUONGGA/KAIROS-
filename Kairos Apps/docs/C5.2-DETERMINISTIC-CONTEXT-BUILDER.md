# C.5.2 Deterministic Context Builder

## Purpose

Convert one day's sanitized `Kairos Event` records into a bounded JSON envelope for the LLM. The envelope is
independent from the Desk Timeline and uses `kairos.summary_context@1`.

## Selection policy

`kairos.llm_context.build_day_context(report_date)` queries only canonical allowlisted fields. It reruns the
C.5.1 quality gate, sorts by `occurred_at` then `event_id`, deduplicates matching source/kind/title within ten
minutes, and prefers agent completions or errors before ordinary messages when the budget is limited.

The selected events are finally returned in chronological order with stable references: `E001`, `E002`, and
so on. The builder never includes `event_id` or `raw_payload` in its LLM envelope.

## Budget and hash

Kairos Settings now provides two non-secret limits:

- `Summary Context Max Events`: default `150`, valid range `1`–`500`.
- `Summary Context Max Characters`: default `50000`, valid range `500`–`200000`.

When a context exceeds its character budget, the builder truncates an individual summary with
`…[truncated]`; it never slices the serialized JSON. Its `meta` block records source, selected, excluded,
deduplicated, and truncated counts plus exclusion reasons.

### Risk: truncation is lossy

Truncating summaries and dropping events after the event or character budget is exhausted can omit late-day
work, individual occurrences, or details that appeared only at the end of a summary. The result is bounded
and may be incomplete; `meta.truncated_count`, `meta.excluded_event_count`, and `meta.exclusion_reasons`
expose the loss but cannot recover it. If the final envelope is still over budget, the builder removes the
latest selected events, so recent work may be dropped too. Do not treat a generated summary as a complete
audit log; raise the limits or chunk the day and summarize in stages when completeness matters.

`canonical_json()` uses sorted keys and compact UTF-8 JSON. SHA-256 of that exact representation becomes
`context_hash`, so the same event set and policy produce the same hash.

uses C.5.1's sanitized timeline.
